# Конвертер в приложении: что уже есть в API и что нужно нарисовать

Документ для разработчиков приложения (sberAct). Конвертер подключается одной
строкой `app.include_router(router)`, поэтому **всё серверное ниже уже работает
в приложении** — не хватает только интерфейса к нему.

Наш собственный фронт (`frontend/`) используется только при локальной отладке
конвертера; в приложении он не участвует. Он может служить примером: все вызовы
собраны в `frontend/src/api.ts`, их применение — в `frontend/src/ScanConverter.tsx`.

---

## 1. Два ограничения, о которые легко споткнуться

**Прокси пропускает только GET и POST.** В `python-backend/app/main.py`:

```python
@app.api_route("/convert/{conv_path:path}", methods=["GET", "POST"])
```

Поэтому ни один маршрут конвертера не использует PUT или DELETE — настройки
сохраняются POST-запросом.

**Повтор POST без `job_key` создаёт вторую задачу.** В `webApi.ts` повторная
попытка даётся только путям из `IDEMPOTENT_POST_PATHS`, и добавлять туда
`/convert/scan` или `/convert/native` имело смысл только после появления ключа
идемпотентности — теперь он есть (см. §3). Без ключа повтор запустит
распознавание того же файла второй раз: это двойное время и двойная память.

---

## 2. Маршруты

Все пути — относительно прокси приложения (`/convert/...`).

| Метод и путь | Зачем |
|---|---|
| `POST /convert/warmup` | Прогрев моделей. Отвечает за ~10 мс, греет в фоне 1.8 с. Приложение уже его вызывает |
| `GET /convert/health` | Готовность окружения одним ответом. **Всегда 200**, смотреть поле `ready` |
| `GET /convert/settings` | Профиль и дефолт доочистки: что определило железо, что выбрал пользователь, что применится |
| `POST /convert/settings` | Сохранить выбор пользователя |
| `GET /convert/profile` | Короткая версия: действующий профиль и `llm_default` |
| `POST /convert/analyze` | Скан или нативный PDF (без OCR, доли секунды) |
| `POST /convert/scan` | Запуск распознавания |
| `POST /convert/native` | Запуск конвертации нативного PDF |
| `GET /convert/status/{job_id}` | Статус, прогресс, стадия, ошибка с кодом |
| `POST /convert/cancel/{job_id}` | Отмена задачи |
| `POST /convert/polish/{job_id}` | Доочистка готового документа моделью по кнопке |
| `GET /convert/log/{job_id}?tail=16384` | Лог задачи (диагностика) |
| `GET /convert/download/{job_id}` | Готовый DOCX |

## 3. Что нарисовать и где

### 3.1 `services/webApi.ts` — вызовы

Рядом с существующими (строки 222–270) добавить `convertCancel`, `convertLog`,
`convertHealth`, `convertSettings`, `convertPolish`.

**Разбор ошибки.** При отказе сервер отдаёт `detail` объектом, а не строкой:

```json
{"detail": {"code": "PDF_ENCRYPTED",
            "message": "PDF защищён паролем.",
            "hint": "Снимите пароль в любой программе для работы с PDF…",
            "detail": "needs_pass=1"}}
```

`new Error(detail)` на таком объекте даст `[object Object]`. Показывать надо
`message` и `hint`; `code` — для своих решений, `detail` — в лог.

**Сетевой сбой.** `fetch` бросает `TypeError` («Failed to fetch»), когда сервера
нет вовсе. Это сообщение браузера, по нему пользователю делать нечего —
замените его на «Сервер конвертера не отвечает…».

**Ретраи.** После появления `job_key` можно добавить `/convert/scan` и
`/convert/native` в `IDEMPOTENT_POST_PATHS` — но только если запрос несёт
`job_key`. Одно нажатие кнопки = один ключ (например `crypto.randomUUID()`), все
повторы этого запроса идут с тем же ключом. Ответ на повтор содержит
`reused: true` и тот же `job_id`. Повтор после `status: "error"` даёт новую
задачу: это уже осознанная вторая попытка.

### 3.2 `features/convert/ConvertScreen.tsx` — шаг конвертации

1. **Плашка готовности при входе на шаг.** `GET /convert/health`: если
   `ready: false` — показать `problems` и подробности критичных строк
   (`items[].critical && !ok`). Иначе пользователь узнаёт об отсутствии языков
   Tesseract только после загрузки файла и минуты ожидания.
2. **Кнопка «Отменить»** рядом с полосой прогресса →
   `POST /convert/cancel/{job_id}`. Коды: `200` — задача снята из очереди,
   `202` — остановится на ближайшей проверке (итог придёт обычным опросом),
   `409` — прервать нечем (нативный режим идёт внутри pdf2docx, доочистка — один
   вызов модели), `404` — задачи нет.
3. **Ветка ошибки** (`status === "error"`, строка ~240): показывать `error` и
   `error_hint`, а также кнопку «Подробнее» → `GET /convert/log/{job_id}`.
   Отдельно стоит обработать два кода: `CANCELLED` — это не ошибка, а отмена
   пользователем; `INTERRUPTED` — сервер перезапускали во время работы.
4. **Терпимость опроса к обрывам** (тик на строке 228): 5–6 повторов с
   нарастающей паузой вместо немедленного провала. Задача идёт на сервере, и
   один обрыв keep-alive не должен её «ронять». Исключение — `404`: задачи нет,
   повторять нечего.
5. **Кнопка «Доочистить текст»** после `done` для скана, если
   `polished === false` → `POST /convert/polish/{job_id}`. Смысл: модель стоит
   ~1.6 ГБ и минуты времени, поэтому на слабой машине её не включают заранее —
   пользователь сначала получает документ, видит жёлтые подсветки и сам решает.
6. **Поле `warning`** из ответа `/convert/scan` и из статуса: предупреждение о
   текстовом слое в скан-режиме или о нехватке памяти под этот файл. Не ошибка,
   работу не запрещает.
7. **Галочка «iim»** (доочистка) — ставить по `llm_default` из
   `/convert/profile`, а не всегда включённой: на слабой машине она по
   умолчанию выключена.

### 3.3 `features/settings/SettingsDialog.tsx` — настройки

Селектор «Режим использования ресурсов» на четыре значения:
`auto | lean | balanced | full`. Текущее значение — `override.profile` из
`GET /convert/settings` (пусто = «Автоматически»), сохранение —
`POST /convert/settings` с полем `profile`.

Замерено на корпусе из 8 сканов:

| режим | время | пик памяти |
|---|---|---|
| `lean` (экономный) | 256 с | 1421 МБ |
| `balanced` | 214 с | 1654 МБ |
| `full` (полный) | 215 с | 1952 МБ |

Автовыбор: меньше 6 ГБ ОЗУ или 2 ядра → `lean`; меньше 12 ГБ или меньше 4 ядер
→ `balanced`; иначе `full`.

Если `locked_by_env: true`, профиль задан переменной окружения
`CONVERTER_PROFILE` — селектор надо заблокировать и объяснить причину, иначе
выбор пользователя молча не применится.

Там же разумно держать дефолт доочистки: `llm_default` в том же POST.

## 4. Коды ошибок

Приходят в `error_code` статуса и в `detail.code` отказов. `error_hint` всегда
содержит действие, понятное пользователю.

| Код | Когда |
|---|---|
| `NOT_A_PDF` | Не PDF, пустой файл, картинка с расширением `.pdf` |
| `PDF_ENCRYPTED` | Файл под паролем |
| `PDF_CORRUPTED` | Повреждён, не читается, 0 страниц |
| `TESSERACT_MISSING` | Нет `vendor/tesseract` |
| `MODELS_BROKEN_PARTS` | Модели не собраны из кусков `*.partNNN` |
| `OUT_OF_MEMORY` | Не хватило памяти |
| `DISK_FULL` | Нет места на диске |
| `PATH_NON_ASCII` | Системный TEMP недоступен по ASCII-пути |
| `LLM_UNAVAILABLE` | Доочистка не загрузилась (документ при этом цел) |
| `CANCELLED` | Отменено пользователем |
| `TIMEOUT` | Не уложилось в срок |
| `INTERRUPTED` | Сервер перезапускали во время работы |
| `INVALID_SETTINGS` | Неизвестное значение настройки |
| `INTERNAL` | Остальное; `detail` несёт текст исключения |

Задачи переживают перезапуск сервера: статус и готовый DOCX доступны по тому же
`job_id` после рестарта, потому что состояние лежит рядом с файлами задачи.

## 5. Переменные окружения

| Переменная | Смысл |
|---|---|
| `CONVERTER_PROFILE` | `auto\|lean\|balanced\|full`. Старше выбора пользователя |
| `CONVERTER_WARMUP` | `off` — не греть модели (экономит ~230 МБ резидентно) |
| `CONVERTER_JOB_TIMEOUT_S` | Срок на задачу, по умолчанию 1800; `0` — без срока |
| `CONVERTER_JOB_LOG_LEVEL` | `DEBUG\|INFO\|WARNING\|off`, по умолчанию `INFO` |
| `CONVERTER_SETTINGS_PATH` | Где хранить настройки пользователя |
| `CONVERTER_OCR_WORKERS` | Число страниц, распознаваемых одновременно |
| `CONVERTER_LLM_UNLOAD` | Выгружать ли модель доочистки после работы |

---

## 6. Чего в API пока нет

* **Лог запуска сайдкара в файл.** Сейчас stdout уходит в `console.log`
  Electron, и если конвертер не поднялся вовсе, задачи ещё нет — значит нет и
  `job.log`. Это единственный случай, когда диагностику с машины пользователя не
  достать.
* **Чистка рабочей папки задач.** `%TEMP%/convert_api_jobs/` хранит PDF, DOCX и
  лог каждой задачи и не чистится сама.
